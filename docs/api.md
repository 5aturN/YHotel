# HTTP API

Интерактивная схема OpenAPI доступна по адресу `/docs`. Даты передаются в формате `YYYY-MM-DD`; дата выезда исключается из интервала проживания. Ответы используют JSON.

## Аутентификация

`POST /api/auth/register` создает аккаунт. Пароль должен содержать не менее 12 символов. `POST /api/auth/login` принимает email и пароль и возвращает короткоживущий bearer-токен. Передавайте токен как `Authorization: Bearer <token>`.

## Номера

`GET /api/rooms/availability?check_in=2030-01-04&check_out=2030-01-07&guests=2` возвращает номера, готовые к размещению и свободные на всем интервале.

Внешние сервисы используют тот же запрос через `GET /api/integrations/rooms/availability`. Для этого маршрута обязателен заголовок `X-API-Key`, заданный переменной `YAOTEL_API_KEY`.

## Бронирования

Все операции требуют bearer-токен.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/bookings` | Создать бронь для текущего гостя |
| `GET` | `/api/bookings` | Получить список собственных броней |
| `GET` | `/api/bookings/{booking_id}` | Получить собственную бронь |
| `DELETE` | `/api/bookings/{booking_id}` | Отменить собственную бронь |

Тело запроса для создания:

```json
{
  "room_id": 1,
  "check_in": "2030-01-04",
  "check_out": "2030-01-07",
  "guests": 2
}
```

Создание возвращает `201` и статус `pending`. Цена хранится и возвращается в копейках. Отмена возвращает `204` и сохраняет запись со статусом `cancelled`; отмена после заселения невозможна.

## Коды ответов

`200` — запрос выполнен; `201` — ресурс создан; `204` — бронь отменена; `401` — отсутствует или недействителен токен/API-ключ; `403` — бронь принадлежит другому гостю; `404` — номер или бронь не найдены; `409` — пересечение дат, дубликат аккаунта или недопустимое состояние брони; `422` — данные не прошли проверку; `503` — обязательная настройка сервиса отсутствует.
