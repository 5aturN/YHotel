# Архитектура

## Обзор

ЯОтель — модульный HTTP-сервис на FastAPI. Маршруты принимают и проверяют запросы, слой сервисов применяет правила бронирования, репозиторий выполняет запросы SQLAlchemy, а модели хранят пользователей, номера и бронирования. Расчет стоимости вынесен в отдельный модуль.

```text
HTTP-клиент
    -> Маршруты FastAPI и схемы Pydantic
        -> Сервисы бронирования и аутентификации
            -> Репозитории SQLAlchemy и модели
                -> SQLite или PostgreSQL
        -> Модуль SMTP-уведомлений
```

## Каталоги и модули

| Путь | Назначение |
|---|---|
| `src/yaotel/api.py` | HTTP-маршруты, аутентификация, преобразование ошибок в HTTP-ответы |
| `src/yaotel/auth.py` | Хеширование паролей и выпуск/проверка access-токенов |
| `src/yaotel/config.py` | Переменные окружения и локальный `.env` |
| `src/yaotel/db.py` | Engine, сессии, схема и начальный каталог номеров |
| `src/yaotel/models.py` | Таблицы пользователей, номеров и бронирований |
| `src/yaotel/notifications.py` | Отправка подтверждений через SMTP |
| `src/yaotel/pricing.py` | Расчет стоимости в целых копейках |
| `src/yaotel/repository.py` | Запросы к базе данных |
| `src/yaotel/schemas.py` | Валидация запросов и формирование ответов |
| `src/yaotel/services.py` | Правила доступности, создания и отмены бронирований |

## Данные

- `User`: нормализованный email, хеш пароля, состояние аккаунта и дата создания.
- `Room`: номер, категория, вместимость, базовая цена и состояние готовности.
- `Booking`: владелец, номер, даты проживания, число гостей, сумма и статус.

Активные статусы бронирования блокируют пересекающийся интервал. Даты трактуются как полуоткрытый интервал: дата выезда не оплачивается. Отмена меняет статус на `cancelled`, не удаляя запись.

## Ошибки и ограничения

Входные данные проверяются Pydantic и сервисным слоем. Некорректные данные возвращают `422`, недоступный номер — `409`, отсутствующий объект — `404`, попытка работать с чужой бронью — `403`. Схема создается при запуске приложения; перед обновлением существующей production-базы требуется отдельная стратегия миграции.

В production следует использовать HTTPS, PostgreSQL, секрет-хранилище, резервные копии и мониторинг. Приложение не хранит платежные реквизиты.
